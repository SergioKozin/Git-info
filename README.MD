# Git info



\_\_



## Команды







Сделать папку репозиторием — **git init**



«Разгитить» папку, если что-то пошло не так, — **rm -rf .git**



Проверить состояние репозитория — **git status**



**Подготовить файлы к сохранению — git add, git add --all, $ git add . # добавить всю текущую папку**



**Выполнить коммит — git commit, $ git commit -m 'Мой первый коммит!'**







**Если выполнить команду git commit без параметра -m, вы попадёте в другую программу — редактор текста vi. Таким образом git предлагает вам ввести сообщение о коммите.**

**Людей, привыкших к современным визуальным средам IDE, этот редактор может немного шокировать. Дело в том, что его разрабатывали очень давно и с тех пор многие принципы построения пользовательских интерфейсов поменялись. А способ, которым нужно работать с vi, стал непривычен.**

**В первую очередь, нужно понять, что vi может работать в двух режимах: управление и вставка. В режиме управления vi запускается по умолчанию. В этом режиме вы не сможете ввести текст, но в нём работают команды управления, вызываемые с помощью символа :. Самое простое, что вы можете сделать, попав в vi при коммите, это выйти из него с помощью команды :q! , где «q» означает Quit (англ. уйти), а восклицательный знак «!» подтверждает, что нужно выйти без сохранения изменений — не важно, были ли эти изменения сделаны или нет.**

**Если же вы всё же решитесь освоить vi, важно запомнить, что переход в режим вставки выполняется с помощью кнопки i (от англ. Insert — вставить). В этом режиме вы можете набрать нужное вам сообщение. Затем нужно с помощью кнопки Esc перейти в режим управления и выполнить команду :wq — она сохранит изменения и закроет редактор. А если вы хотите выйти из редактора, но не хотите сохранять изменения, выполните уже знакомую вам команду :q!.**



**Ещё раз о разнице между git add и git commit**

**Сначала команда git add сообщает Git, какие именно файлы нужно сохранить и какую их версию. Затем с помощью команды git commit происходит само сохранение.**



**Просмотреть историю коммитов — git log**





**Итого:**



**Инициализация репозитория**

**git init (от англ. initialize, «инициализировать») — инициализируй репозиторий.**

**Подготовка файла к коммиту**

**git add todo.txt (от англ. add, «добавить») — подготовь файл todo.txt к коммиту;**

**git add --all (от англ. add, «добавить» + all, «всё») — подготовь к коммиту сразу все файлы, в которых были изменения, и все новые файлы;**

**git add . — подготовь к коммиту текущую папку и все файлы в ней.**

**Создание коммита**

**git commit -m "Комментарий к коммиту." (от англ. commit, «совершать», «фиксировать» + message, «сообщение») — сделай коммит и оставь комментарий, чтобы было проще понять, какие изменения внесены.**

**Просмотр информации о коммитах**

**git log (от англ. log, «журнал \[записей]») — выведи подробную историю коммитов.**

**Просмотр состояния файлов**

**git status (от англ. status, «статус», «состояние») — покажи текущее состояние репозитория.**













**Привязать удалённый репозиторий к локальному — git remote add**



**git remote add origin git@github.com:%ИМЯ\_АККАУНТА%/first-project.git**



**Убедиться, что репозитории связаны, — git remote -v**







**Отправить изменения на удалённый репозиторий — git push**



**Вы уже прошли весь «цикл коммита»: подготовили файлы с помощью git add,** 



**закоммитили их с комментарием командой git commit -m. Осталось загрузить содержимое локального репозитория на GitHub. За это отвечает команда git push (от англ. push — «толкать»).**

**В первый раз эту команду нужно вызвать с флагом -u и параметрами origin (имя удалённого репозитория) и main или master (название текущей ветки). Флаг -u свяжет локальную ветку с одноимённой удалённой. Как вы связывали локальный и удалённый репозитории, так же и здесь нужно дополнительно связать ветки.**





**Процесс копирования удалённого репозитория на локальный компьютер называется клонированием. Клонирование репозитория — обычно первое, что делает разработчик на новом месте работы. Вы сымитируете эту ситуацию в уроке.**

**Клонировать репозиторий — git clone**





**Команда git clone автоматически связывает локальный и удалённый репозитории. То есть если в GitHub-репозитории что-то поменяется (например, добавятся коммиты), вам не нужно будет заново клонировать его. Достаточно будет выполнить команду, которая обновит вашу копию.**

**Убедитесь в том, что репозитории связаны, командой git remote -v.**
